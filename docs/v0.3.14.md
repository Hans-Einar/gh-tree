# gh-tree v0.3.14 — Active worktree deployment and stash cockpit

v0.3.14 makes **Active worktree** a stable deployment/test target instead of implicitly following whatever local worktree already contains the selected Git object.

## Selection versus activation

- In **Branches**, `Enter` first opens Branch context as before.
- In **Branch context**, `Enter` on the Branch section deploys that branch tip into Active worktree. The deployment is detached so the selected branch may remain checked out in an agent/Codex worktree.
- In **Commits**, `Enter` deploys the exact selected commit detached into Active worktree.
- In **PRs**, `Enter` fetches/verifies the PR head and deploys that exact head detached into Active worktree.
- `Ctrl+Enter` is deliberately different: it makes an existing local worktree containing the selected branch/commit/PR the Active worktree.

Deploying into an existing worktree always opens a centered confirmation dialog. The primary worktree cannot be retargeted.

## Dirty Active worktree and Git stash

A dirty Active worktree is never reset or overwritten. The deploy dialog offers `s` to create a Git stash containing tracked and untracked changes and then continue. gh-tree-created stash messages record the origin worktree, branch/HEAD, base SHA and timestamp.

Git stashes belong to the repository, not to one worktree. The Active worktree pane therefore lists the repository's stashes even after that worktree has been retargeted. Manually created stashes are also visible and are labeled as unmanaged.

The **Stash** list supports:

- `Enter` / `d`: inspect stash patch
- `a`: apply without deleting the stash
- `p`: confirmed pop
- `x`: confirmed drop

Apply/pop requires a clean target worktree. Conflicts are surfaced by Git and are never auto-resolved. Cleanup never deletes untracked files.

## Active worktree cockpit

Launch and Stash are shown side-by-side with whitespace as an invisible divider:

```text
Launch                         Stash
  Concept1 · npm dev:lan         stash@{0} issue-59 4 files
  Concept1 · npm build           stash@{1} unmanaged 2 files
```

`Alt+L` focuses Launch, `Alt+S` focuses Stash, and left/right moves between them.

## Navigator and pane help

Branches checked out by a local worktree receive a fixed-column `*` marker. Context-specific keyboard help is rendered in a reserved bottom row inside the active pane; inactive panes keep that row blank. The global footer is limited to global pane navigation and quit.

Branch context also behaves vertically: Down from Branch enters Commits, while Up from the first commit returns to Branch.

## Console activity

An interactive CMD/PowerShell/bash session waiting for input is displayed as `idle` and does not keep the rolling activity animation alive. Launch processes continue to show animated running/starting state while they execute.
