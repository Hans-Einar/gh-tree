# API--001 — normative protocol design

State: DRAFT; part of REFDES--001 under #52. This is a design contract, not
permission to implement or freeze boundaries. The later seven BCs specialize
these shared rules without inventing competing identities or lifecycles.

<a id="a1"></a>
## A1. Type ownership and construction

`internal/domain` owns comparable, immutable value objects with private fields,
validating constructors, equality and value accessors. It owns no JSON tags,
filesystem parsing, clocks, transport errors, DTO collections or allocators.
Zero values are invalid unless an explicitly named option represents absence.

| Value | Required invariant |
|---|---|
| RepositoryID | Nonempty opaque scope token; Remote and LocalCommon scopes cannot compare equal. |
| WorktreeID | LocalCommon RepositoryID and nonempty administrative key; path/display/HEAD excluded. |
| BranchID | RepositoryID, Local or RemoteHead kind, exact valid full branch name; `origin/x` is never a substitute for a remote-scoped branch identity. |
| PRID | Remote RepositoryID and positive number. |
| OID | Exactly 40 SHA-1 or 64 SHA-256 hex characters, canonical lower case, nonzero; object format retained. |
| Revision | RepositoryID plus exact OID; adapter verifies commit type/existence in the intended object database. |
| Head | Closed Attached(BranchID, Revision), Detached(Revision), Unborn(BranchID) variants; local repository scopes agree. |
| StashID | LocalCommon RepositoryID plus exact stash OID, independent of reflog position. |
| LaunchPointID | WorktreeID plus unambiguous length-delimited provider/project/member key; no source-version or label in equality. |
| SessionID | Positive uint64; Runtime allocates monotonically for its registry lifetime, refuses wrap, never routes by decoded provider/kind. |

Branch names reject Git-invalid ref syntax by a documented pure validation rule;
the Git adapter still asks native Git to validate before mutation. Domain exact
targets are closed variants: CommitTarget(Revision), BranchTarget(BranchID,
ExpectedRevision), PullRequestTarget(PRID, ExpectedHeadRevision). A PR head
Revision uses its head repository scope. Application resolves that remote scope
to an explicitly verified local object; equal OID bytes alone do not change
repository identity. LatestBranchQuery is an API query, never an exact target.

Boundary scope minting is deterministic: Git physically resolves its common
directory, separates the primary worktree key from linked administrative keys,
and uses the canonical absolute locator without blanket path case folding.
Windows resolves final handle paths and volume identity, preserving component
case rather than collapsing case-sensitive directories; Unix resolves links
and preserves path bytes. GitHub resolves the authenticated host, lowercases its
DNS host and GitHub owner/repository components, strips only URL transport
syntax and one terminal `.git` suffix. A different host is a different scope.
No network lookup, URL parsing or path canonicalization happens in Domain.
Unresolvable identity is an error. Clone relocation creates a new local scope;
Persistence retains old preferences for explicit migration/recovery.

`application/api` owns operations, query generations, observations, settings,
launch definitions, invocation specifications, session snapshots and read models.
`application/ports` owns interfaces and private plan/version handles. Concrete
adapter types may not occur in either public surface. Values crossing boundaries
are copied on receipt and return, including slices, maps, byte buffers and nested
members. `context.Context` and ordinary Go errors are control/diagnostic values,
not mutable product state. No port callback can mutate State.

## A2. One public coordinator protocol

The Go surface has the following shape (names and ownership are normative;
ordinary constructor/options scaffolding may be private):

~~~go
type Client interface {
    Submit(context.Context, Request) (Receipt, error)
    Confirm(context.Context, ConfirmationID, Choice) error
    Cancel(OperationID) error
    Next(context.Context) (Event, error)
    Shutdown(context.Context) ShutdownResult
}
~~~

Request contains a closed Command or Query payload plus Correlation. It cannot
contain both. Correlation contains a client intent token and, for queries only,
a QuerySlot plus generation. These tokens are echoed, never interpreted as
adapter freshness or Git authority. The coordinator allocates OperationID and
Sequence, never accepts either from callers. Receipt is the assigned ID and
Accepted sequence. Submit context bounds admission only; once accepted, operation
lifetime belongs to the coordinator and ends through Cancel, supersession or
shutdown. An already-canceled request is rejected before acceptance.

`Next` has exactly one consumer. Event is a closed union of Accepted, Progress,
ConfirmationRequested, OperationTerminal, SessionChanged and ProjectionInvalidated,
with global Sequence and relevant OperationID/Correlation or SessionID/sequence.
OperationTerminal contains its typed result or diagnostic, cancellation intent,
effect report and recovery information. It is emitted exactly once per accepted
operation even if a port panics (recovered at the coordinator boundary), refresh
fails, the client navigates away, or shutdown begins. A recovered panic after a
possible side effect is Indeterminate, never proof of no change.

Admission reserves space for Accepted, at most one confirmation and Terminal.
Initial limits are 64 live accepted operations and 256 unconsumed critical
envelopes; refuse with Busy before accepting when either reservation fails.
Progress and invalidation hints coalesce; critical events never drop. Consuming
Terminal releases its reservation. Keep the latest 256 delivered terminal records
for diagnostics; this history is not a durable execution journal. Admission stops
during shutdown. Cancel and Shutdown bypass normal admission so a full UI queue
cannot prevent cleanup. Shutdown owns an internal drain when the public consumer
has detached, awaits use-case and Runtime barriers, then closes the stream.
Context timeout means the caller stopped waiting; it does not abandon cleanup.

Next removes an event only when returning that event successfully. Cancellation
before that delivery leaves it pending; a successfully returned event remains
valid if the context concurrently cancels. The host always applies or explicitly
drains successful deliveries before requesting the next one.

No timed polling of product state is required by View. Runtime uses its own
session sequence, which Application normalizes without inventing another
session registry. Natural session exit produces SessionChanged, not a second
terminal event for the already completed Start operation.

## A3. Closed request and result inventory

Each row denotes distinct typed payloads and matching results, not a bag of
optional fields or a generic `Execute(string, any)` adapter call. All worktree
requests carry WorktreeID; path entry is limited to create/configuration requests.
Pagination carries explicit limit and cursor/skip, and responses carry completeness.

| Query | Inputs | Result |
|---|---|---|
| Navigator | remote namespace/repository scope and optional associated local scope | PRs, branch relations, worktrees, available capabilities and per-source diagnostics |
| BranchContext / Commits | exact branch/PR/commit target, page | verified endpoint, immutable commit facts, pagination and source version |
| Graph | local scope, roots/filter, page | commits/edges plus App-owned PR/worktree/branch annotations and completeness |
| Diff | closed CommitParent, CommitPair, IndexToWorktree or HeadToIndex comparison; exact endpoints/path filter | bounded patch/file changes, comparison label semantics, truncation and diagnostics |
| WorktreeStatus | WorktreeID | Head, index/worktree changes, upstream, locks/occupancy observations |
| Stashes | local common scope | exact StashIDs, labels, order as presentation metadata and observation version |
| LaunchPoints | WorktreeID | discovered and saved definitions, default identity, incomplete-source diagnostics |
| Sessions / SessionOutput | optional WorktreeID; SessionID and byte offset for output | immutable session snapshots; bounded output chunks/gaps and next offset |
| Preferences | resolved scope | effective settings, explicit legacy/migration diagnostics and source versions |

| Command | Inputs and policy | Terminal result |
|---|---|---|
| ActivateWorktree | selected WorktreeID and expected preference version | committed active context plus storage outcome |
| SaveNavigation | scope, namespace/folder intent and expected storage version | saved intent and commit outcome; no View state persistence |
| CreateWorktree | vacant path, exact target, Detached or create-new-local-branch mode | verified new WorktreeID/Head; no overwrite existing destination |
| RetargetWorktree / Deploy | selected WorktreeID or named configured WorktreeTarget, exact target, detach/attach policy | verified target context and effects/recovery; primary/current restrictions explicit |
| CreateBranch | WorktreeID, exact start Revision, new name, checkout choice | created branch identity and optional verified Head; no existing branch rewind |
| Fetch | explicit local/remote binding and ref scope | fetch generation and resulting observed refs |
| Pull | WorktreeID, expected Head and observed resolved upstream | fetched and verified fast-forward or explicit refusal/partial result |
| Push | WorktreeID, expected local Revision, explicit remote branch, optional set-upstream choice | remote effect and separate upstream-config effect |
| StagePaths / UnstagePaths / StageAll | explicit path set or all mode plus observed status/index version | resulting index observation; staging never implicitly commits |
| Commit / StageAllAndCommit | WorktreeID, expected index/Head/status, literal message and explicit existing-index or observed-stage-all policy | exact new Revision and verified branch/index effects; failed commit can leave a known staged index |
| RestoreTracked | path set and expected index/worktree observation | restored-from-index result and retained-original recovery records |
| StashCreate | WorktreeID, expected dirty state, message and include-untracked choice | exact created StashID and cleanup effects |
| StashApply / StashPop / StashDrop | exact StashID and target WorktreeID where relevant | applied/index/conflict/drop effects; AppliedStashRetained is distinct |
| CreatePullRequest | explicit base RepositoryID/BranchID, head RepositoryID/BranchID and expected published head Revision, title/body/draft | verified remote PR identity/URL or remote-effect uncertainty |
| SaveLaunch | WorktreeID, exact discovered/saved selection version, alias, make-default choice and explicit replace-existing-alias approval/version when applicable | atomic saved definition/default and storage outcome |
| StartLaunch | WorktreeID, saved/default or exact discovered selection and geometry | new SessionID with established resource ownership |
| OpenTerminal | WorktreeID, explicit configured shell policy and geometry | new interactive SessionID/capabilities |
| WriteInput / ResizeSession | SessionID, copied bytes or positive rows/columns | accepted transport outcome or stopping/unsupported diagnostic |
| InterruptSession | SessionID | capability-specific delivery result; never synonymous with tree Stop |
| StopSession / RestartSession | SessionID, restart geometry if supplied | old cleanup barrier and, only after success, new SessionID |

Configured WorktreeTarget remains a Persistence setting projected by Application,
not an unvalidated path that bypasses the create/retarget safety protocol. Worktree
diff retains the baseline index-to-worktree behavior and receives an accurate
label. StageAll remains distinct. Saved launch command overrides and first-saved
default behavior are preserved. Graph semantic messages remain verbatim facts;
the View formats annotations separately.

## A4. Errors, effects, confirmation and cancellation

Use a stable ErrorCode enum including Invalid, Unavailable, NotFound, Busy,
Canceled, Superseded, StaleObservation, ConfirmationStale, Conflict, Permission,
Unsupported, IOFailure, ProcessFailure, CleanupIncomplete and Indeterminate.
Diagnostic contains code, safe message, operation/source context and optional
structured details. Native exit/stderr/path detail remains diagnostic; parsing
localized stderr must not manufacture domain facts. Do not classify all absence
as NotFound or all nonzero exits as no change. Sensitive environment/credentials
are excluded from snapshots and logs.

EffectReport lists independently observed facets: object/recovery creation,
worktree bytes, index, local refs/HEAD, remote refs/PR, storage and Runtime
resources. Each is NotStarted, VerifiedNoTargetChange, AppliedVerified, Partial
or Indeterminate with post-observation and recovery locator when applicable.
Effects are not an ordered enum from which success can be guessed. Cancellation
is a separate requested flag. AppliedVerified plus failed refresh keeps the known
mutation result and marks its projection unavailable. Remote timeout may be
Indeterminate; do not retry a PR mutation blindly.

The use case asks its port to Prepare a typed mutation plan without holding locks
across UI delay. Plan contains an adapter-private opaque handle and a safe immutable
summary: exact identities/OIDs, dirty/index/path effects, allowed choices and
recovery behavior. Coordinator issues a single-use ConfirmationID bound to that
OperationID, request, plan, worktree, summary and allowed choices. One operation
requests at most one confirmation; a required second decision ends with a new
explicit request requirement. Confirm only resumes that original operation.

Revalidation happens under reacquired repository/storage guards before publication.
A stale plan cannot silently refresh into the user's old approval. Unrelated
refresh/navigation cannot approve or cancel a pending mutation. Dirty deploy may
offer Cancel or StashThenDeploy; the approval binds the original dirty capture and
exact deployment target, and the created stash/recovery is returned even if the
later deploy fails. Query supersession cancels only older queries in the same
slot; all still receive terminal results. Per-common-repository mutation queues
serialize cooperating Git operations across linked worktrees. Runtime lifecycle
serializes per SessionID, and active-context writes serialize per app session.

<a id="a5"></a>
## A5. Application-owned ports

Ports are typed interfaces grouped by capability to allow narrow use-case fakes.
Implementations may share one adapter registry. Interfaces below state required
families; each request/result is the corresponding API semantic value, with opaque
port-owned PlanToken/SourceVersion handles where needed. No adapter owns another
adapter, API Client, UI callback or application workflow.

| Port group | Required methods and authority |
|---|---|
| GitFacts | ResolveLocal, ListWorktrees, ObserveStatus, ResolveExact, ListRefs, ListStashes, ReadCommits, ReadGraph, ReadDiff; returns local facts and completeness only |
| GitMutations | PrepareCreate/Retarget/Stage/Commit/Restore/Stash/Branch/Push, ExecutePrepared, ReleasePlan, Fetch, Reconcile; typed plan variants exclude unsupported cross-operation reuse |
| RemoteFacts | ResolveRepository, ListBranches, ListPullRequests, ObservePullRequest; pages carry interval/observation identity and completeness |
| RemoteMutations | CreatePullRequest with explicit base/head scope and prevalidated expected published revision; return created/unchanged/indeterminate remote effect |
| LaunchDiscovery | Discover and Resolve; worktree-scoped definitions/source versions in, validated immutable Invocation out; no process start or JSON write |
| Storage | LoadUserConfig, LoadPreferences, LoadRunConfig, CommitUserConfig/Preferences/RunConfig with expected version; complete immutable document and precise commit outcome |
| Sessions | Start, Snapshot, List, ReadOutput, Write, Resize, Interrupt, Stop, Restart, NextEvent, Shutdown; one registry and explicit phase/exit/cleanup facts |

An unexecuted plan holds no native locks/resources and is released on confirmation
cancel, terminal completion or shutdown. Plan admission is bounded by accepted
operations; stale/released tokens cannot execute. Recovery journals are separate
from ephemeral plans and remain until explicit safe recovery/cleanup disposition.

Pull orchestration is Application Fetch -> exact upstream observation -> prepared
fast-forward. Deploy is exact resolution -> plan -> optional confirmed stash ->
revalidate -> execution -> reconciliation/projection. Git's ExecutePrepared may
perform native mechanical substeps, but cannot fetch remote API data or decide
which worktree the user meant. Discovery receives decoded saved definitions;
Storage receives an Application-selected run document. Start receives only a
validated copied Invocation and cwd identity, never a provider-specific object.

GitHub uses an authenticated `gh api`/GraphQL transport with explicit host and
bounded responses (default page size 100, cap 10 pages per refresh, explicit More
at cap). API errors preserve partial observations only when independently valid.
Create PR uses explicit repository-qualified head/base fields; it cannot push,
fork or choose a local checkout. Application verifies published head/base facts
and reports drift. A remote service has no generic transaction with local Git;
results carry the observation interval rather than a fabricated global snapshot.

Git and GitHub short-command transports are adapter-private, distinct from Runtime
sessions. Bound machine output and diagnostics separately (initial ceilings 16MiB
and 256KiB; narrower diff/provider bounds still apply), own one root waiter and
join copied pipe readers. Read commands have a 30s budget, mutating/network/hook
commands 120s, with a separately bounded 2s forced pipe-drain/join period after
cancellation. These are configurable adapter construction limits, not provider
guesses or UI timeouts. Record truncation and limit refusal explicitly.

Default CommandContext kills only the direct root. A canceled command with forced
pipe closure does not prove descendants cleaned or mutation rollback. Return
started/reaped/transport-cleanup-known flags and effect uncertainty. Application
retains unresolved mutation/cleanup notices, blocks unsafe automatic retry in the
affected scope and includes residuals in shutdown even if the initiating modal
closed. Concrete persistent-session cleanup guarantees apply only to Runtime's
owned sessions. No adapter may call Runtime's private supervisor or another adapter
to hide a missing command-transport contract. If a command path needs stronger
descendant ownership, implement/review it within that adapter or accept a design/
BC dependency change first; do not infer it from root exit.

## A6. Runtime, discovery, storage and UI shared values

SessionSnapshot contains SessionID, WorktreeID, copied display/start specification,
capabilities, phase (Starting, Running, Stopping, Cleaned, CleanupFailed), optional
exit code/signal, cleanup status/residuals, per-session sequence and output range.
Exit is independent of cleanup: exited root with descendants is not Cleaned.
Capabilities explicitly distinguish input, resize, terminal ETX and tree stop.
Registry rejects foreign/evicted IDs; cleaned eviction cannot hide live resources.
Output chunks are copied raw bytes with stream, offsets, truncation/gap and
sequence. Consumers must request missed offsets after a coalesced hint.

Runtime reserves its non-droppable cleanup event before accepting a new session.
NextEvent has one Application consumer and an acknowledged cursor; final cleanup
events are retained until acknowledged independently of the 256 cleaned-snapshot
history. When 256 unacknowledged critical events are reserved, new Start refuses
before acquisition. Output/running hints may coalesce, cleanup outcomes may not.
Runtime Shutdown remains callable outside normal admission and Application keeps
draining through that barrier. Neither registry may evade boundedness by moving
unconsumed outcomes into an unbounded side queue.

Invocation contains executable, literal argv, explicit environment policy,
physically validated cwd locator/identity, terminal mode and positive geometry.
Shell execution is explicit: npm/Make use argv, interactive shell uses configured
shell policy. SourceVersion differs from LaunchPointID. Resolve binds manifest,
provider/member and saved override version; Runtime verifies cwd at acquisition.
Unknown provider versions and redirected project paths fail explicitly.

Saved selection additionally carries the exact alias and StorageVersion. Two
aliases may reference the same underlying LaunchPointID; State must retain which
saved alias was selected. Alias equality preserves existing case-sensitive exact
bytes, distinct from labels/provider keys. A conflicting existing alias requires
explicit replacement approval bound to its prior version. First save becomes
default only when no default exists or make-default was explicitly selected.
Display ordering uses a total tuple (folded label, exact label bytes, stable ID),
including configured targets, without treating display folding as identity.

StorageVersion is an opaque whole-document version, including missing-file state.
CommitOutcome distinguishes NotCommitted, Committed, CommittedDurabilityUncertain
and Indeterminate. Load distinguishes absent, corrupt, unsupported and valid with
preserved unknown fields. Persistence returns migration candidates; Application
chooses unambiguous semantic mappings. No adapter silently chooses active worktree.

State.Update(State, Input) returns a new State plus declarative Effects. Input is
a closed user/event/layout/tick union; no Tea command or concrete adapter enters
the reducer. Effects contain typed API submissions/cancel/confirm and presentation
timer requests. State.Project returns a copied `tuistate/viewmodel.Snapshot`:
semantic rows, selection/focus, modal target/choices, safe text content, session
presentation and viewport. View.Layout(snapshot, dimensions) returns rectangles
used by both Render and host resize dispatch. View.Render is pure. Host retains
one presentation timer and maps output offsets into safe line presentation; it
never infers working/idle or rewrites commit messages to encode business joins.

Layout also reports whether the current confirmation identity and choices can
be presented, tagged with modal identity and viewport generation. State accepts
that measurement only for its current modal/viewport and suppresses approval
while presentation is inadequate or awaiting a new matching measurement. View
does not choose or execute an action. Tiny viewports retain cancel/navigation
and a bounded resize notice; expanding restores the original operation/token.

All seven BCs must preserve these type and lifecycle rules. A required incompatible
signature/state change after freeze is BC-CHANGE, not a worker-local convenience.
