## Decision

Use one registry and lifecycle machine in `internal/runtime`, with private platform implementations. Use native Windows creation/Job/ConPTY handling through the already pinned `golang.org/x/sys/windows`, and a Unix session implementation using explicit `Setsid`/controlling-terminal setup, whole-session membership observation and group cleanup. Do not use `xpty.Start`/`WaitProcess` as the lifecycle backend. A registry is not itself containment; terminal state requires the platform and I/O barriers below.

Keep Domain limited to SessionID. Application owns OperationID, upward DTOs and operation policy. Runtime owns allocation, resource truth and session synchronization. Neither provider names nor numeric ID ranges route operations.

## Concrete Windows creation and rollback

Use one Job per session. The Job is unnamed, non-inheritable and configured with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`; do not enable either breakaway flag. Do not request `CREATE_BREAKAWAY_FROM_JOB`. Nested outer Jobs are permitted when the OS accepts them; incompatible parent restrictions are an explicit failed Start, with no uncontained fallback. Windows associates ordinary CreateProcess descendants with their parent's Job. It is not a security boundary against a child asking an external service/WMI to launch unrelated work. [Microsoft Job semantics](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects), [nested Jobs](https://learn.microsoft.com/en-us/windows/win32/procthread/nested-jobs).

Ordered acquisition:

1. Reserve SessionID/Starting entry under the registry's shutdown gate. Copy the normalized specification. Resolve executable/argv/cwd/environment before process creation; reject embedded NUL and invalid dimensions. Preserve explicit shell interpreter/command overrides and Windows command-line quoting; do not infer an interpreter from a provider name.
2. Create/configure Job. Keep an acquisition stack immediately after each successful handle allocation. Job/process/thread handles must never be child-inheritable.
3. For launch pipes, create explicit stdin/stdout/stderr endpoints and STARTUPINFOEX HANDLE_LIST containing only child endpoints; use STARTF_USESTDHANDLES, bInheritHandles=true and CREATE_NO_WINDOW. Close parent copies of child endpoints after CreateProcess. For ConPTY, create both channel pairs and HPCON with flags=0, then the PSEUDOCONSOLE attribute; bInheritHandles=false, no extra console window. Use correct standard-handle flags; the probe verifies output reaches the ConPTY pipe. Keep the output drain independent of input and close.
4. Call native `windows.CreateProcess` with `CREATE_SUSPENDED | CREATE_UNICODE_ENVIRONMENT | EXTENDED_STARTUPINFO_PRESENT` and retain both `ProcessInformation.Process` and `.Thread`. Supply mutable UTF-16 command line, explicit application path and environment block as applicable. Attribute payloads/environment buffers remain live through the call; use `runtime.KeepAlive` where needed. No user root instruction can execute while its primary thread remains suspended. [Creation flag contract](https://learn.microsoft.com/en-us/windows/win32/procthread/process-creation-flags).
5. Assign the suspended process to the already configured Job. Assignment failure: TerminateProcess the still-suspended root, wait for its process handle to signal, then close process/thread and partial terminal/pipe/Job resources. Never resume on failure. The thread handle is not discovered later by enumerating threads.
6. Install wait/output ownership and recheck accepted cancellation/shutdown intent before ResumeThread. Cancellation here follows the same suspended-root cleanup. Resume exactly once; check its return/error. Close the thread handle after successful resume; retain the process handle through wait and exit-code acquisition. Start succeeds only after this gate and ownership installation. An immediately exiting root is a valid short successful start followed by independently ordered cleanup.

Atomic PROC_THREAD_ATTRIBUTE_JOB_LIST could avoid the suspended interval, but it is not the selected path: neither pinned wrapper exposes it and x/sys does not name the constant. Adding an unverified numeric constant would not establish feasibility. Suspended native creation is sufficient and was probed.

Rollback is a real lifecycle, not a best-effort defer label. If killing/waiting/closing fails or times out, publish an operation failure with a retained SessionID and residual handles/resources in `cleanup-pending`; do not publish FailedStartCleaned or Stopped. A failed attempt can finish as an Application operation while Runtime remains responsible for cleanup. Never reuse its ID.

## Windows stop and terminal barrier

Terminal Ctrl+C is the PTY input byte 0x03, with terminal line-discipline/application-dependent effects. It is an explicit input capability, not proof of a foreground process signal or a whole-tree stop. A short grace interval may send it once; Stop always proceeds to whole Job termination when required. Non-PTY CREATE_NO_WINDOW sessions have no general safe console Ctrl+C/CTRL_BREAK channel; advertise no graceful-interrupt capability and proceed to force termination. Do not broadcast GenerateConsoleCtrlEvent or temporarily attach gh-tree to an unrelated console.

After grace, TerminateJobObject is a request, not the terminal barrier. Retain the Job and query BasicAccountingInformation until ActiveProcesses=0; a completion port may wake the waiter, but missed notifications must not create false success. Wait the retained root process handle, read exit status and close it. Zero active Job membership proves no ordinary owned Job process remains; root exit alone does not. [TerminateJobObject](https://learn.microsoft.com/en-us/windows/win32/api/jobapi2/nf-jobapi2-terminatejobobject).

Reject new writes/resizes at stopping. Cancel/join the bounded input writer through the owned os.File; keep the output reader draining while ClosePseudoConsole runs on a different owner goroutine. ClosePseudoConsole may produce a final frame. Windows before 11 24H2 can block indefinitely if output is not drained; newer Windows returns before all clients have disconnected. Therefore neither an HPCON close call nor root Wait alone completes the session. Wait for terminal teardown and output completion, close remaining pipes, join every I/O/wait owner, delete attribute storage and close Job. [Pseudoconsole channel/teardown guidance](https://learn.microsoft.com/en-us/windows/console/creating-a-pseudoconsole-session), [version-specific close semantics](https://learn.microsoft.com/en-us/windows/console/closepseudoconsole).

A configured final-output deadline may close the output pipe and mark discarded trailing output explicitly. It must not hide a still-running close worker or failed resource barrier. Deadline exhaustion means CleanupPending/ResidualResources, not Stopped. Native OS calls cannot be made universally cancellable by wrapping them in a goroutine; an unjoined worker is still a residual resource. Normal supported-platform tests must prove bounded completion, including an older supported Windows version.

## Unix process/session ownership

Use a separate SID for **both** launch and PTY roots: `SysProcAttr.Setsid=true`. A new session also creates the initial process group. Do not combine Setsid with an unnecessary Setpgid on that same child; that can fail for a new session leader. For a PTY, attach the slave as child fds 0/1/2 and set Setctty=true/Ctty=0 before exec. Go performs these changes in the child before the user executable, and reports setup failures through its exec error pipe. Close the parent slave immediately after Start. For pipe sessions, manually owned *os.File endpoints avoid hidden exec copy goroutines. Use ordinary `exec.Command`, not request-lifetime CommandContext killing only the root.

Killing only `-rootPID` is insufficient: an ordinary interactive shell moves foreground pipelines and background jobs into **other PGIDs in the same SID**. Retain/observe the SID and enumerate all its live members. Current concrete options:

| Target | Implementable membership observation |
|---|---|
| Linux (386/amd64/arm/arm64) | Enumerate numeric `/proc` entries and read stat fields PID, state, PPID, PGRP, session and start ticks. Parse the parenthesized comm field correctly. Do not read argv/environment/user files. Re-read identity/SID before signals. x/sys PidfdOpen/PidfdSendSignal provides stable per-process signaling on kernels that support it; use it there. |
| Darwin (amd64/arm64) | x/sys `SysctlKinfoProcSlice("kern.proc.all")` exposes PID, start time, process state and PGID; `Getsid(pid)` supplies actual numeric SID. Do not confuse Eproc.Sess (a kernel address-shaped field) with SID. A permission/incomplete census is a cleanup error. |
| FreeBSD (386/amd64/arm64) | x/sys has Getsid/signals but no typed SysctlKinfoProcSlice/KinfoProc equivalent. Use a bounded adapter-private `/bin/ps -ax -o pid= -o ppid= -o pgid= -o sid= -o stat=` with LC_ALL=C and strict numeric/state parsing, or replace it only with reviewed ABI-specific sysctl code. The base-system ps source explicitly maps sid to ki_sid. It must not depend on Linux-only `/proc` or GNU ps flags. |

[Pinned Darwin x/sys source](https://cs.opensource.google/go/x/sys/+/v0.44.0:unix/syscall_darwin.go), [Apple getsid contract](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/getsid.2.html), [FreeBSD 14.3 ps keyword source](https://raw.githubusercontent.com/freebsd/freebsd-src/releng/14.3/bin/ps/keyword.c). FreeBSD commands above are source-checked and compile-checked, **not native-run here**. Preflight the required observation capability before accepting a session, and fail Start explicitly if it cannot be established.

Preserve SID identity until cleanup: do not call Cmd.Wait/Process.Wait as soon as the root exits. Detect its terminal/zombie state from membership observation, initiate remaining-session cleanup, and retain the unreaped direct-child leader until all live members are gone. Then reap it exactly once to obtain final status. Go Start does not automatically reap this child. This avoids root PID/SID recycling while cleanup still targets the old session. The leader's natural exit starts cleanup; it does not report a completed session while background jobs remain.

Stop sends SIGTERM to owned groups (PTY may first offer ETX as an input courtesy). After bounded grace, force cleanup freezes observed members/groups with SIGSTOP, repeats complete SID census to discover forks/new job groups, then SIGKILLs all owned live groups/members and verifies no live members remain. Confirmed stopped threads cannot create new descendants; repeat until quiescent or deadline. Retain all pending ownership records and the leader's unreaped identity until the barrier. A root already terminal does not skip descendant cleanup. Zombies cannot run and are not live descendants; Runtime reaps its direct root, while nonchild zombie reaping remains the OS/parent's responsibility.

Use identity/SID revalidation before every group/member signal, never signal PID/PGID 0, -1 or an arbitrary stale remembered number. On Linux stable pidfds remove PID-reuse ambiguity for member signals. Darwin/FreeBSD portable numeric group signaling still has a check-to-signal race for nonleader groups; a precheck is not an atomic handle. Retaining the root protects the initial group/SID, not every other group. Native tests must exercise rapid group churn and reject identity uncertainty rather than guess. The accepted guarantee is session ownership for ordinary job-control trees, not a security sandbox against hostile concurrent PID churn.

Explicit setsid/daemon escape and work launched through an external service are outside a POSIX SID's containment: a portable SID does not prohibit those actions. Record observed escape/permission/census uncertainty as residual failure; never call an observed escaped process stopped. Do not claim discovery of every unobserved deliberate escape. Linux delegated cgroups or FreeBSD per-session reapers could strengthen that policy but are not portable drop-in replacements: cgroup delegation is not generally available to an extension, and x/sys lacks a ready FreeBSD reaper wrapper. These must not become undocumented prerequisites or remove ordinary PTY support. [Linux cgroup ownership](https://www.kernel.org/doc/html/latest/admin-guide/cgroup-v2.html), [FreeBSD reaper API](https://man.freebsd.org/cgi/man.cgi?manpath=FreeBSD+14.4-RELEASE+and+Ports&query=procctl&sektion=2).

The final REFDES/BC must explicitly accept this platform ownership scope and the remaining numeric-signaling limitation. It must not silently replace the no-owned-live-descendant success gate with “root killed” or “signal sent.” If stronger atomic protection against arbitrary job-group/PID churn is required, that is a further design mechanism to resolve before claiming it implemented; this appendix does not prove such protection on Darwin/FreeBSD.

## Unified protocol constraints

- Registry reserves a nonzero monotonically allocated uint64 SessionID once; reject exhaustion. Starting sessions participate in Shutdown. Keep global lock only for allocation/membership/gating; per-session coordination serializes mutation. Retained failed/stopped history is bounded separately from live or residual resources, which cannot be evicted.
- Distinguish Starting, Running, Stopping/CleanupPending and terminal Cleaned states. Exit reason is separate from phase: natural/nonzero/signal/requested/failed-start. A nonzero root exit is not a resource-cleanup failure; conversely exit zero does not prove cleanup.
- One operation terminal result per OperationID and one session-cleaned lifecycle event per SessionID are different facts. Start success closes its operation while the session remains running. Later natural exit carries SessionID and causative/start correlation without completing Start twice. Concurrent Stop requests join one cleanup and each accepted distinct operation receives its own exactly-once result; session cleanup event remains singular.
- Stop acceptance latches stop intent and continues resource ownership under a Runtime lifetime/cleanup budget when caller context ends. Caller timeout reports Pending/Residual with SessionID, never stopped success. Start cancellation before establishment rolls back; after established persistent Start, ending the original request context does not kill the session.
- Restart serializes on the old session and deduplicates by operation key. It awaits the complete old barrier, then requests a new ID using the immutable specification and latest explicit geometry. Failure of old cleanup prevents replacement. Cancellation after old cleanup but before replacement leaves old terminal and starts nothing. Failed replacement remains a distinct failed new ID.
- Shutdown closes admission first, includes in-flight starts, attempts every live/pending session under one overall budget with bounded parallel cleanup, and returns all residual SessionIDs/stages/errors. Success requires every barrier and subscription/worker join. Composition preserves primary UI/init error plus aggregate teardown errors; a cancelled root context is not the teardown wait context.
- Output is bounded raw bytes plus stream kind, absolute byte/sequence offsets, retained-start offset and truncation/gap marker. Preserve chunks without line-scanner limits; UI transport never blocks the OS output drain. Presentation interprets safe terminal controls; Runtime does not strip ANSI into lifecycle truth. A bounded write queue copies input and rejects overflow explicitly. Resize validates positive int16-compatible terminal dimensions, serializes with Close and rejects stale/unsupported requests.
- Lifecycle delivery must be replayable from retained authoritative session/outcome records or reliably drained; a full output queue cannot drop the only terminal result. Output notifications may coalesce with offsets. Snapshots deep-copy nested values. Application consumes monotonic per-session sequence and maintains operation deduplication; TUI owns intent/focus relevance.
- Expose only observable activity: lifecycle, terminal availability and output observation. No shell-idle/working claim from provider, PID, output silence or session existence.

Suggested initial bounds for the BC to fix centrally: 2 seconds graceful, 3 seconds force/resource join, one 8-second aggregate shutdown budget; injectable in tests. Platform unsupported graceful mechanisms are explicit and skip grace. These are operational limits, not a promise that an unresponsive kernel can always be cleaned in that time. Exceeding a bound is a truthful residual failure and prohibits Restart success.

## Addendum RTF-02 — replace numeric Unix signaling with session-local helpers

Date: 2026-09-06. Authority: Issue #52 bounded design followup; starting governance HEAD `58f1cb9eda941db0941cbb8e04e6a0559a3ca896`. A separate safety reviewer correctly rejected the numeric nonleader-PGID check-to-signal race. **This addendum supersedes the earlier Unix signaling recommendation, its acceptance of that race, and the proposed unreaped-user-root mechanism.** Windows decisions remain unchanged. The earlier no-native-Unix statement describes the initial pass; native Linux evidence is added below.

### Selected ownership and signaling mechanism

Start a small private **supervisor** from the same installed gh-tree executable, as Runtime's direct child and the new SID/initial PGID leader. The supervisor remains alive while the user root, ordinary foreground/background groups, and signal helpers exist. Spawn the user root in another PGID in that SID. The user root may exit and be reaped promptly; it no longer pins the SID. The supervisor pins the session independently and owns one waiter for every direct child.

Runtime/supervisor must **never** signal a census-selected numeric PID or `-PGID`. A census PGID is only a candidate for safe acquisition:

1. Supervisor spawns the same executable's private signal-helper mode with Go `SysProcAttr{Setpgid:true, Pgid:candidate}`. Do not set Setsid or Foreground on this helper. Go performs setpgid in the child **before exec** and reports setup failure through the exec error pipe.
2. The kernel permits joining only a group in the caller's session. A vanished group normally produces EPERM; a number reused by a group in another SID cannot grant authority. The special case where a vanished candidate equals the newly allocated helper PID can create only the helper's own new group inside the owned SID, which is harmless.
3. After exec and private-channel validation, the helper verifies **its own** `getsid(0)==supervisorPID` and `getpgrp()==candidate`, with candidate positive and different from supervisor PGID. A mismatch exits without signaling. This is a check of the executing helper's acquired membership, not a stale check on another process's number.
4. The live helper now pins the acquired group object. Even if all original members exit, that group cannot disappear and be recycled while the helper remains a member. After exec, its parent cannot move it with setpgid; the helper implementation never calls setsid/setpgid again. After an authenticated commit frame it calls **`kill(0, permittedSignal)`**, which targets its own current group. The zero-argument exception is confined to this verified helper; kill(-1), public numeric kill APIs and parent-side numeric group signaling remain forbidden.

The race is therefore removed by acquiring membership and signaling the acquired current group, not by narrowing a timing interval. A vanished candidate causes re-census; an acquired group with no original members affects only its helper. A permission/setup/protocol error never enables a numeric fallback. Failure to kill any remaining owned member is detected by the terminal census and returns residual failure.

Source support: [Apple setpgid contract](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/setpgid.2.html); [FreeBSD 14.3 setpgid implementation](https://raw.githubusercontent.com/freebsd/freebsd-src/releng/14.3/sys/kern/kern_prot.c); Go 1.25 `syscall/exec_linux.go`, `exec_libc.go`/`exec_libc2.go` for Darwin, and `exec_freebsd.go` establish setpgid before exec. Apple's inspected kernel path for kill(0) obtains the caller's current process-group reference, rather than looking up a caller-supplied numeric group. [Apple signal implementation](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/bsd/kern/kern_sig.c). These Apple main-source links are corroborating current source, not a claim of a tested macOS release; supported-version native tests remain required.

### Private dispatch and control protocol

Composition performs only an early dispatch call to a Runtime-owned internal entry, before normal CLI parsing, config/prerequisite reads, adapter construction or TUI startup. Runtime owns all supervisor/helper implementation and protocol types under its folder. This is not constructor/business workflow in Composition, a shared process layer or an Application API for arbitrary signals.

The executable has no supported CLI accepting PID/PGID/signal. A fixed private mode marker alone is insufficient to enter a working internal mode. Require separately inherited anonymous control/reply endpoints, verify their descriptor kinds, protocol version and a fresh random per-session nonce, then validate the expected parent/SID/role. Missing, malformed, replayed or mismatched handshake fails closed with no normal-bootstrap fallback and no user command or signal. Use the absolute trusted running executable, never PATH/cwd lookup of a helper name.

The inherited endpoint is the authority capability; nonce and monotonic request sequence prevent replay/cross-session confusion. A nonce received from an arbitrary named file or public socket is not authentication. Do not place a bearer secret, target PGID or signal in argv/environment, open a named control socket, or accept control data from PTY/stdin/output. Length-prefix/cap frames, reject unknown fields/opcodes, bind copied immutable start specification to the accepted SessionID/OperationID, and bound reads/writes. Supervisor commands from the parent are Start/Stop/Abort/Release and observations, not arbitrary group numbers; supervisor chooses groups from its owned-SID census.

Each signal helper receives only its own fresh inherited endpoints. Prepare includes supervisor identity, candidate PGID, fixed signal enum, request sequence and nonce. The helper validates its acquired membership, replies Joined, and waits for matching Commit. Closing the pipe or cancellation before Commit exits without a signal. After Commit, cleanup remains owned even if the caller stops waiting. Repeated commits do not send repeated signals. User roots receive **none** of these endpoints or secrets; mark Runtime control FDs close-on-exec in their owning process and do not list them in user-child ExtraFiles. A user command invoking gh-tree with the private marker consequently fails its missing-endpoint gate. This does not claim a sandbox against hostile same-UID code that can inspect another process's memory/descriptors.

Inherited Unix pipe descriptors require explicit nonblocking/poller setup before `os.NewFile` if deadlines are used. The native probe found that an inherited blocking descriptor otherwise returns `file type does not support deadline`; merely setting a context does not make the read cancellable. Keep one framed decoder per connection and close/join its reader/writer on teardown. The production protocol is a required implementation contract, not fully implemented by the small probe.

### PTY, root exit, stop and supervisor release

- Runtime opens/resizes the PTY with immediate rollback ownership, launches supervisor with Setsid=true, Setctty=true/Ctty=0 and slave at child fds 0/1/2, then closes its slave copy. Supervisor stays in its private initial PGID. It starts the shell in a new group with `Setpgid:true, Foreground:true, Ctty:0` while its fd 0 is the controlling slave. Helpers use private pipes/NUL standard streams and never take foreground control. This preserves ordinary shell-created foreground pipelines and background job groups in the owned SID.
- Supervisor obtains a startup handshake before executing any user specification. Cancellation/EOF before user Start closes partial PTY/control resources and exits without a user root. A cancelled/failed child Start is reconciled with the actual Start result; if the root was created, it already belongs to the SID and must pass cleanup. Do not use CommandContext to kill a supervisor that has running owned groups.
- Once established, request-context completion does not kill the session. On root exit, supervisor records/reaps that exact child and initiates remaining-session cleanup; it does not disappear with the root. Root exit status and session resource completion remain different facts. Parent-channel EOF latches shutdown and keeps cleanup running; reporting to a vanished parent cannot block it.
- Grace uses a verified helper for SIGTERM per observed group, with optional terminal ETX courtesy as previously specified. On escalation, helper SIGSTOP freezes each observed group; repeat complete census and acquisition until no new live groups can run/fork, or return a bounded residual failure. A STOP helper must stay parked after its syscall instead of voluntarily exiting immediately: the probe observed a helper exit before its own stop was observable, even while other members were stopped. Retain its exact child/wait ownership until CONT/KILL cleanup.
- A newly spawned helper can join an already stopped group and run; SIGCONT resumes it, and SIGKILL terminates the group including the signaling helper and parked STOP helpers. For KILL, no post-syscall success reply is expected. An acknowledged Commit plus the helper's expected signal termination is execution evidence, **not** proof all members died. Re-census, inspect errors and join all direct waiters. A successful group signal may still leave a credential-changed member; any live member prohibits Stopped.
- Reject unexpected live members in the supervisor's reserved PGID as residual ownership failure; do not kill that group early or ignore them. Ordinary roots start in their own group, so foreground/background shell job control does not require joining the reserved supervisor group. Deliberate changes into that group are not silently converted into successful cleanup.
- When no live SID member except supervisor remains and all user/helper waits are joined, supervisor sends Quiescent and rejects further Start/signal work. Parent keeps the supervisor identity alive through this barrier, then sends Release while its output/control readers remain active. Supervisor closes its final slave/control resources and exits last. Parent completes PTY/output/control joins and waits/reaps the supervisor exactly once before publishing session Cleaned. Do not wait for output EOF before Release while supervisor retains the slave. If the parent is gone after quiescence, supervisor can exit safely without a Release reply.
- Supervisor crash or inability to acquire a helper is an observable cleanup failure, not permission for the parent to signal remembered numbers. Keep the session residual, forbid Restart success and report the failed ownership stage. A direct child's unreaped identity can support its own cancellation before any user process exists, but it is not authority over census-selected descendants. Never have concurrent waiters on the same child.

This mechanism retains the previously stated POSIX SID scope: ordinary job-control descendants are owned; deliberate setsid/daemon escape or external-service launch is not prevented. Observed escape remains a residual failure. The numerical race is **not** an accepted limitation of this corrected design. FreeBSD reaper or Darwin private audit-token APIs are unnecessary to eliminate that specific race and are not introduced.

### Adapter-private short Git/gh commands are a different contract

The retired generic `internal/process` runner must not reappear, and Git/GitHub/Discovery/Persistence must not call Runtime as another adapter or invoke its private supervisor protocol. Their small command transports remain adapter-private under the acyclic design. Composition's private-mode dispatch does not expose an execution service to them.

`exec.CommandContext` normally cancels by killing the direct root; CombinedOutput/Wait can also wait on descendants retaining pipe handles. Neither establishes this Runtime session guarantee. A short-command adapter must bound captured bytes, retain exactly one root waiter, define its Cancel and WaitDelay policy, close/join its own pipe/copy workers, and report whether the root was started/reaped, output was truncated and cleanup remains unknown. Do not call a timed-out command's mutation rolled back or its descendants cleaned merely because Wait returned after closing pipes. Never make a successful global shutdown, safe mutation retry or stable post-mutation assertion from that weaker evidence.

Cancellation before spawn can be definitive; after a state-changing Git/gh command starts, Application must retain its effect/cleanup uncertainty and reconcile under that port's mutation contract. If the chosen short-command contract requires descendant cleanup rather than only a reaped root and joined adapter resources, the adapter needs an explicitly owned/reviewed platform mechanism within its own layer (or a separately accepted dependency-policy change); default CommandContext is not that mechanism. This bounded Runtime followup neither implements nor verifies those other adapters and does not silently extend the persistent-session proof to them.
