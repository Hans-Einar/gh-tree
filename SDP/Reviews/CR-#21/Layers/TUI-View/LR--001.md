## Layer responsibility

TUI View owns rendering into terminal cells: responsive panel geometry, borders/colors, focus and mnemonic appearance, row/detail/graph/diff formatting, context help, modal composition, bounded output display, and activity appearance from supplied facts. Target: internal/tuiview/.

It must not call Application/Git/GitHub/Runtime/Persistence/Launch Discovery; own focus, selected identity, modal identity, input routing or operation correlation; reconstruct branch/PR relationships; decide destructive authorization; poll sessions; persist preferences; or modify any supplied snapshot. Bubble Tea scheduling and terminal I/O belong to the presentation host, with product operations routed through Application.

The accepted TUI State reducer remains the sole interaction authority. Application supplies reconciled product facts and capabilities. View can abbreviate a list label or choose a color, but cannot replace the exact Revision/StashID/SessionID behind that label or turn unknown observations into absent/equal/idle facts.

### Evidence interpretation

M01 is an observed read side effect, not proof that View launches or mutates a process. The normal service's capability lookup is currently registry membership; it can still change rendering independently of its supplied snapshot and prevents backend-free testing. Value receivers do not make slices/maps or referenced services immutable.

M03 is a functional display defect: shrinking the screen can remove a list whose controller can still focus/act on it. The probe does not execute a stash action or claim a destructive result. At 160x32 the metadata-only result occurs even without long PR data; long paths/full OIDs increase the competing line budget.

M06 is a reviewability defect alongside the stronger accepted confirmation findings. The modal itself does not show retained ExpectedRevision; background text may sometimes contain it, but clipped/dimmed background is not a reliable confirmation target contract. View must not create or validate ConfirmationID; it renders the already bound facts/choices.

M10 proves returned strings can exceed width, contain broken UTF-8 or retain CSI controls. No actual terminal escape was executed and no exploit is asserted. Launch lineBuffer preserves scanner text, whereas terminalLines already strips ANSI and handles CR/backspace. A raw supplied terminal snapshot in a unit test would not by itself prove bypass of that Runtime normalizer; the control probe uses a launch-provider snapshot.

## Immutable input and cycle-free ownership

Recommend a small presentation DTO package inside the accepted TUI State layer, for example internal/tuistate/viewmodel/. It contains semantic display data only and imports selected Domain values/standard types, not the parent reducer, Application implementation, Bubble Tea or Lip Gloss. It is not an eleventh logical layer or a Domain dumping ground.

Cycle-free candidate dependency graph:

```text
tuistate -> application/api + domain + tuistate/viewmodel
tuiview  -> tuistate/viewmodel + approved rendering libraries
presentation host (Composition-owned) -> tuistate + tuiview + application/api
tuistate/viewmodel -> domain + standard value types only
```

State maps accepted Application projections into this DTO. Neither State nor DTO imports tuiview. The host implements Bubble Tea Model.View by calling the renderer and implements Update by routing keys/events through the single reducer. Composition may import every concrete layer for wiring; the host still uses Application API for product work. Exact package spelling/signatures remain REFDES decisions.

An equally acyclic State-owned DTO in the parent package is possible only if that package never imports View; the leaf package above makes forbidden imports and independence easier to enforce. Do not have both tuistate call tuiview and tuiview import tuistate to obtain types. No requirement here promotes Application read models into Domain.

Minimum supplied semantic input:

| Input group | Owner and required distinction |
|---|---|
| Screen / interaction | State supplies mode, one focus path, selected stable IDs, ordered rows, search/edit state, scroll requests, one modal variant and its bound operation/confirmation identity. View derives visible indexes only. |
| Product facts | Application supplies exact revisions, explicit attached/detached/unborn-or-unsupported state, active worktree, dirty/status facts, scoped branch/PR/worktree relationships and source completeness/freshness. View does not compare names to infer membership. |

Published snapshots must be immutable through ownership transfer or defensive copies. Go value structs with exported slices/maps are not sufficient. Specify nested arrays/bytes/maps, retained snapshots and renderer scratch memory; Render must not sort/append into caller-owned storage. Enforce with before/after deep comparisons and repeated render tests. Shared Domain values remain immutable exact identity.

Local clipping or scroll clamping for a frame is permitted without writing back interaction state. E7 renderStashPatch314 changes a value-receiver copy of stashPatchScroll, not the authoritative field; it is not itself an observed focus mutation. If a reducer needs a new scroll bound, return measurement data through the host and correlate it to the current content/viewport generation.

## Layout, modal and measurement requirements

Treat the full screen as one measured budget including header, breadcrumb, status, global/context help, borders and padding. Use actual terminal cell width, not bytes/runes or Lip Gloss minimum Width/Height as a hard clipping guarantee. Unknown startup geometry may use a fallback; a delivered 39x17 event must not become 100x30.

The later design must choose a small-screen policy preserving access to current focus/selection and modal choices. Possibilities include compact metadata and focus-prioritized panels with explicit navigation, but this review does not select a new UX. Require no panic/negative slice, bounded output, clear unavailable-size state, and recovery on resize without changing selected identity. Do not silently omit stash/launch because their metadata siblings grew.

Modals receive one authoritative variant from State. View does not resolve contradictory independent booleans by precedence or decide which operation owns the dialog. Measure modal content and reserve title/target/actions before clipping or scrolling its body. Long paths/revisions/patches and a dialog larger than the viewport need an explicit policy keeping cancel/confirm meaning accessible.

Keep background composition presentation-only. Existing overlay strips background ANSI then dims it; the new contract may preserve that visual intent with cell-safe composition. It must not mutate focus, invoke a base renderer's backend, duplicate nested dialog frames or remove the only exact target information. Background updates may continue to reflect accepted projections without changing the modal owner.

Renderer/layout output should include visible console content rectangles keyed by SessionID, plus content/viewport generation and visibility. This can come from a pure Layout/Measure function used by Render or a render result computed by the host; Bubble Tea View must not emit asynchronous commands. Compute layout once for both display and measurement.

Host compares current visible measurement to the last dispatched one, correlates it with current session/capability and forwards positive changed rows/columns through Application ResizeSession. Ignore stale measurement/completion and avoid resize-render feedback loops. A hidden pane or modal overlay must have an explicit retain/suspend-sizing policy; it is not an invented 20x4 viewport. Runtime validates capability/session lifetime and owns actual resize; State owns which session is selected.

## Styling, help, activity and output

Use an instance-owned immutable theme constructed from host-provided color capabilities. Retain readable focused/unfocused headers, selected rows, mnemonic emphasis, warning/error/status distinctions and textual focus/activity cues when color is unavailable. Fixed palette choices are visual policy; global mutation and different wrapper palettes are ownership defects. No new theme chooser is required.

Pane and subpane IDs/focus flags must be explicit. panel314's title comparisons and heading311/314's byte indexing of a mnemonic must not define focus or key behavior. Current English ASCII titles avoid the latter Unicode case, but generalized helpers need grapheme-safe tests rather than an inferred current localization feature.

Help derives from the same semantic action/keymap used for routing: mode, pane/subpane, modal, input capture, busy/availability and configured capability. Preserve graph/diff controls and the distinction between shell Tab/completion, Ctrl+C/interrupt, application navigation, stop/restart and quit. At narrow widths prioritize applicable actions without advertising keys that are forwarded elsewhere. Rows and command labels are presentation, actual authorization remains Application.

Runtime/application facts must distinguish session running, terminal alive, stopping/confirmed stopped, observed output and unknown foreground activity. The renderer cannot label an existing terminal "idle" as a factual claim. A star may mean a precisely documented lifecycle observation; animation cannot imply CPU work or foreground-command truth unavailable from Runtime.

Resolve the accepted State review's "View timer ownership" as presentation-policy ownership: View defines the frame mapping and whether supplied presentation activity needs frames; Composition's host schedules/cancels at most one timer and owns its handle/generation. Timer events advance only presentation state and are inert after screen/host disposal. View.Render never starts a timer, polls a backend or handles Application completions. Product subscriptions/polling remain Application/Runtime. Do not recolor arbitrary matching words in commit text, paths or error strings.

Separate three text categories: trusted renderer-generated styling; untrusted descriptive text (repo/PR title, branch, path, commit message, error, launch name); and session output with declared transport semantics. Ordinary external text needs visible-safe control handling before styling. Clip/wrap using display cells and grapheme boundaries while preserving valid ANSI resets for trusted styling; do not split UTF-8, combining sequences or wide glyphs.

Terminal output needs an explicit representation decision coordinated with RT25-M09: current terminalLines is lossy line normalization, not a full VT screen model. It strips cursor-motion sequences and replays the bounded byte ring; launch output follows a different path. Preserve useful baseline CR/backspace/output behavior and declare limitations. If interpretation moves into tuiview, any incremental parser/screen cache is presentation-only, owned by the host and reset by SessionID/output generation; Render still receives an immutable snapshot. Do not add an unrelated terminal-emulator feature or put PTY lifecycle in View.

Bound output bytes/cells/rows and incomplete-sequence handling. Never forward arbitrary OSC/CSI terminal controls from launch logs, patches or metadata as host commands. Diff --no-color prevents Git's own color formatting but does not sanitize control bytes contained in file content. Keep patch payload separate from truncation notices and display the exact supplied source/range; formatting cannot change the Git facts.
