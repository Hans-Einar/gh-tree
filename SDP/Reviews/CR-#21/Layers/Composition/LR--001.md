## Lifecycle / concurrency and root errors

Bubble Tea 1.3.10 defaults to Background without WithContext. Its dispatcher explicitly does not join executing Cmd goroutines at shutdown; cancelling Program does not quiesce product work. Run handles ordinary signals/terminal restoration and reports context/panic errors, but does not own launch/PTY resources. [Pinned tea.go](https://github.com/charmbracelet/bubbletea/blob/v1.3.10/tea.go#L241), [WithContext](https://github.com/charmbracelet/bubbletea/blob/v1.3.10/options.go#L17).

Recommended shutdown ordering:

1. Mark host/Application closing and reject new submissions, including Runtime Start. Invalidate presentation timers and input/effect dispatch.
2. Application quiesces accepted operations and cancels safe reads under use-case policy, retaining outcomes for mutations already begun. UI shutdown alone does not drain Tea commands.
3. Application invokes one Runtime Shutdown. Attempt every session and report all residual failures even after UI failure. Runtime owns containment, escalation, joins and stopping/stopped truth.
4. Keep required event drainage alive until operation/cleanup barriers complete, then join subscriptions/bridges and dispose presentation resources. Do not wait on undrained channels after host Run exits.
5. Restore terminal presentation through host teardown, emit bounded combined diagnostics and return one process result. main alone maps it to exit status after run's defers finish.

Root cancellation initiates shutdown but is not its wait budget. Use a separately bounded teardown context not already cancelled; Runtime retains ownership when caller waiting times out. Exactly one owner coordinates idempotent Shutdown; fallback defer must not race independent cleanup. In-flight Start must establish a registry-owned session included in shutdown or fail with partial-resource cleanup, never register after the final snapshot unnoticed.

| Root outcome | Required observable result |
|---|---|
| Help/argument/default/prerequisite failure before acquisition | No UI/session construction; help success or diagnostic error, with no login/config repair. |
| Constructor/Application initialization failure | Unwind acquired owners in reverse dependency order, including Runtime if acquired; preserve initialization plus all cleanup errors. |
| Normal cockpit/graph quit | Quiesce operations and require complete aggregate shutdown; success only on its accepted guarantee. |
| UI Run/terminal setup failure | Same cleanup; retain UI error even if cleanup also fails. Neither replaces the other. |
| Root cancellation/external termination request | Classified cancellation/exit after bounded cleanup. Distinguish keyboard Ctrl+C intent from OS signal; preserve console interrupt/exit confirmation. |
| Recovered UI panic | Preserve failure diagnostics plus cleanup. Unrecovered panic still unwinds cleanup and reports failure without hiding the panic. |
| Forced OS kill/machine loss | Defers cannot guarantee cleanup; Runtime containment/crash guarantees require platform evidence, not a root successful-Shutdown claim. |

Use typed aggregation or errors.Join-equivalent preserving errors.Is/As and residual SessionIDs. Cleanup failure returns nonzero even after successful UI return. No os.Exit in run/host/adapters; no blank-assignment cleanup; no cancellation-as-rollback for Git/remote/persistence mutations. Diagnostics identify scope/stage without dumping secrets or full configuration.
